# 工程决策基线

状态：已接受。日期：2026-10-16。依据：项目负责人授权由实现方决定原实施计划第 7 节全部待决策项。

本文规定后续实现与验收的默认行为。决策通过不代表功能已实现或生产就绪；当前差距见各节及文末状态表。变更须记录理由、兼容影响和迁移办法，不能通过部署参数静默放松约束。本文提到但配置 schema 尚不支持的选项均为待实现契约，不可直接复制到当前 YAML。

## D01：预算超限

- 默认 `token.on_exceeded=reject`。应用可显式选择 `downgrade` 或 `stop_stream`，配置不能自动切换为无限制放行。
- 降级必须重新检查模型能力、结构化输出、地域、数据等级、价格、准入与剩余预算；原模型、降级模型、重试共享父预算，不能通过换模型重置预算。
- 流式硬上限始终有效。`stop_stream` 表示消费中达到阈值时关闭流并结算已产生用量，不代表其他动作可以继续越界输出。未交付内容和供应商在途用量仍可能计费；同步调用和供应商缓冲不承诺可抢占的零超支。
- 生产成本硬预算须配置受支持模型的价格和输出上限，缺失价格默认拒绝。usage 缺失时保守估算并标注来源；供应商实际用量超过预留时如实记账、阻止后续准入，不截断账面金额来伪装未超限。

当前：Run 内预算、显式降级、流停止与生产严格预设已实现，另可注入 RedisBudgetStore 组合共享配额；缺价拒绝发生在调用前，usage 拒绝保留消费结算。开发缺价默认为 observe。Redis 持久故障切换保证需部署验收；使用见 `RUNTIME.md`、`OPERATIONS.md`。

## D02：跨进程预算的一致性

- 首版选择中心化 Redis 原子预留/结算，不实现本地额度租约或最终一致的离线放行。内存预算仅承诺本地 Run 的边界。
- 一个预算作用域只有一个权威写入端；同一 Lua/事务原子检查全部适用上限并建立 reservation，使用幂等 request/reservation ID，金额使用整数微单位或精确 Decimal 编码。Redis Cluster 的同一原子事务所需键必须位于同一 slot。
- 连接失败、超时、未知提交结果均拒绝新增准入；先按原 ID 查询/幂等重试，不能改 ID 再扣一次，也不能自动降为 memory。开发环境可显式启用 memory，但健康信息须标记已失去跨进程保证。
- worker 崩溃或 reservation 超时不自动退还可能已消耗的额度。先隔离为待核对/保守占用，再依据 provider usage、可验证的未执行结果或人工核对结算；状态 TTL 不能成为重复花费入口。
- Redis 原子性不等于故障切换下的持久强一致。生产验收须覆盖持久化、单写 fencing、故障恢复和预算 epoch；无法证明已确认预留未丢失时暂停新准入并核对，禁止在异步复制切主后直接宣称零超售。首版不支持跨地域多活预算。

当前：已提供独立 RedisBudgetStore；采用单 slot Lua、整数微美元、幂等预留/结算、无 TTL 退款、epoch 暂停和显式审计核对/恢复。fake Redis Lua 并发和未知提交测试已通过，另有真实 Redis CI 契约。多层作用域联合事务、真实主备故障演练与持久性证明尚未完成；不能将 Lua 原子性当作故障切换下的全局强持久保证。

## D03：事件故障、背压与保留

- 事件显式分为普通观测与必需审计。普通指标、性能和调试事件默认 fail-open；队列满可丢弃最旧的普通事件，必须累计 dropped 计数并提供可读健康状态，不能静默丢弃。
- 策略发布/回滚、审批决定、预算账本变更、权限与安全拒绝属于审计。必需审计不采样；采用持久本地 outbox + 至少一次投递，消费端按稳定 event ID 去重。不能以普通遥测队列替代审计 outbox。
- 生产审计模式在策略变更或受保护副作用执行前，必须可靠写入意图/授权记录。默认审计写入等待上限 2 秒，本地 outbox 默认上限 256 MiB/进程，二者可配置；远端不可达但本地可靠写入成功时可继续。磁盘不可写或容量耗尽时拒绝新的受保护操作，禁止自动降为丢弃模式。
- 操作已经执行后，投递失败不能伪装为“未执行”或触发自动重放。保留实际结果与 execution-may-have-completed 状态，利用 outbox 恢复；最终结果落盘也失败时明确标记审计完整性故障并暂停后续受保护操作。该模式不承诺对任意外部副作用提供原子事务。
- 默认普通事件保留 7 天，可配置 1–30 天；审计元数据保留 180 天，可配置 30–3650 天。按事件时间与租户策略清理；到期删除覆盖在线数据、索引和归档，备份按已声明的到期轮换策略清除。合法保留冻结须有授权与审计，不能默认无限保留。
- 不保存模型原文、凭证或评估器 reason。outbox 文件须有最小访问权限，持久存储使用部署方提供的静态加密；只有持久化、重放、清理与故障演练完成后才声明可靠审计。

当前：普通事件提供有界队列与默认 7 天清理；必需审计另有 SQLite FULL outbox、意图/结果、审批/安全/预算决定、容量拒绝、重启暂停、核对恢复和幂等持久归档。默认逻辑保留 180 天，保护未投递/未闭合记录。256 MiB 限制针对逻辑载荷，页/WAL/索引须额外配额；加密、ACL、备份到期删除和介质故障由部署验收，不能据此承诺完整保留 SLA。

## D04：缓存默认值与禁止项

- 运行时缓存默认关闭；首版只实现精确缓存。语义缓存独立开关，默认关闭，后续单独验收。
- 仅允许显式白名单中的 `public/internal` 纯模型响应或只读工具结果。初始 TTL 为 300 秒，范围 1–3600 秒；不允许无限 TTL。未知数据等级默认视为不可缓存，策略匹配取最严格等级。
- 永久禁止缓存的类别：`confidential/restricted` 内容；检测到凭证、个人信息或未解决安全发现的输入/输出；审批凭据、会话/访问令牌；`write/irreversible` 工具的请求结果；工具副作用等级未知的结果；错误、取消、超时、不完整流、安全/质量未通过的响应。这里“永久禁止”指类别不允许配置例外，并非永久保留数据。
- 白名单或长 TTL 不能覆盖禁止项。只读工具必须显式声明，幂等写工具也不能通过缓存跳过真实执行、审批或权限检查。
- 键必须包含 tenant/project/environment、用户或授权上下文摘要、模型与参数、Prompt/template 版本、策略版本、数据等级及工具版本；使用规范化序列化和租户域 HMAC，不把原文放入键。无隔离身份不得使用共享缓存。
- 缓存命中仍执行当前权限、安全与质量检查；权限撤销和策略变化须使条目失效。缓存故障按 miss 执行正常准入和预算，不绕过防护；并发击穿保护必须有截止时间。

当前：默认关闭的精确缓存支持显式白名单中的模型响应与版本化只读工具 JSON 结果；内存和同机 SQLite 后端支持身份/策略版本 HMAC 隔离、TTL/LRU、命中复检和清空失效。只读工具命中仍走额度、准入与可靠审计；写入/不可逆、要求审批或幂等键的调用不缓存。网络/语义缓存、流式、自动重试、自定义拦截器及供应商 SDK 对象暂不缓存。权限检查由应用负责并通过授权版本隔离。不标记完整生产缓存就绪；使用与限制见 `CACHE.md`。

## D05：平台、Python 和适配器支持窗口

- 核心 SDK 与本地控制台纳入 Windows、Linux、macOS 支持目标。首批发布验收矩阵为 Windows 11/Server 2022+、Ubuntu 22.04/24.04 LTS、macOS 14+；Windows 10 提供开发兼容，不单独作生产保证。
- 首批 CPython 验收范围为 3.10–3.14，标准带 GIL 构建；PyPy、free-threaded 和更新 Python 版本为实验范围。`requires-python>=3.10` 是安装约束，不能解释为未来所有版本均已验证。Python 次版本退出维护需提前至少 90 天公告，并在后续 minor 版本调整元数据与迁移文档；已结束上游维护的 Python 不作运行环境安全保证。
- 核心包、console、各 adapter 分别发布支持矩阵；不因第三方 adapter 缺失而阻断无依赖 SDK 安装。前端构建目标维持 Node.js 22+，发布验证采用受支持的 LTS 版本和锁文件。
- 每个 adapter 首次发布时确定一个上游稳定 major，在该 major 内验证最新及前一个稳定 minor 的最新 patch；明确下限和 `<下一 major` 上限。版本范围不能超过实际 contract test 覆盖范围，新 major 不自动纳入。
- 保留前一个已支持 minor 至少 90 天迁移窗口；窗口后可在 SDK/adapter minor 发布中提高下限，须公告。安全漏洞、上游停服或已确认不兼容可紧急收窄范围，必须提供原因与迁移路径。第三方新版本须经同步、异步、流式、usage、错误与取消契约测试才能加入支持表。

当前：本次验证环境是 Windows 的 CPython 3.11.0；其余平台/版本尚未有完整发布 CI 证据，不能把目标矩阵写成已全部通过。各第三方适配器仍需逐项登记，不宣称通用 Wrapper 自动覆盖其所有版本。

## D06：控制平面失联、策略有效期与紧急回滚

- 远程模式仅信任已认证、验证签名/完整性、作用域与 schema 的策略快照；本地显式配置不因控制平面故障而自动改变。
- 远程刷新默认每 60 秒进行，带抖动；服务端签发的快照有效期默认 15 分钟，范围 60–3600 秒。断网期间不因失败刷新或重启延长有效期；同时校验有效期和本地单调经过时间，时钟异常不能续期。
- 未过期快照可继续使用；启动时无有效快照或快照过期后，默认拒绝新模型/工具准入。数据安全、权限、审批、幂等与硬预算不允许 fail-open。正在执行的调用保留结算和清理能力；运行中的 Run 在下一次准入时也要检查远程有效期，不能靠旧 Run 无限续用过期授权。
- 必须区分策略可用与预算可用：有效策略不授权绕过 Redis 硬预算故障。遥测连接单独 fail-open，不能导致策略失效。
- 仅 public、显式只读且不受远程硬预算约束的非敏感调用，可由预先签发的策略允许最多额外 5 分钟受限宽限期；默认关闭，宽限不可被客户端无限续期，期满拒绝。其他受保护操作无宽限。
- 普通回滚将已审核旧内容重新发布为更高版本，记录目标内容摘要和回滚原因，客户端不接受版本号倒退。失联紧急回滚只接受部署前分发的、可验证且未过期的签名恢复包；恢复包绑定环境/租户与独立递增恢复序号，有效期最长 1 小时，并要求本地授权操作及审计。
- 恢复包只能保持或收紧当前已知的安全边界；需要放松权限、预算或数据保护的回滚必须重新经在线授权发布。恢复连接后采用更高有效 epoch/version 的已验证策略并记录收敛结果，不能覆盖本地尚未处理的紧急拒绝状态。未具备有效恢复包时保持拒绝，禁止自动退回出厂宽松配置。

当前：已提供 HTTPPolicyProvider、HMAC、作用域与版本高水位、原子缓存、到期拒绝和时钟回拨保护。刷新在新 Run 时按默认 60 秒（0.9–1.0 抖动）触发，没有后台轮询。已有 Run 在下一次真实调用前检查 pinned 有效期。同版本同内容可签名续期，但不能延长已有 Run。恢复使用统一严格递增版本，限定 60–300 秒，必须审计且仅允许保持或降低明确上限；不启用宽限。共享 HMAC 信任及缓存权限见 OPERATIONS.md。

## D07：实时预算与权威成本账本

- SDK 提供实时用量与近似成本，用于预留、准入和运营观测；保留 provider/tokenizer/estimate/unknown 来源、模型和价格表版本，不称为供应商最终账单。
- 控制平面负责导入供应商最终账单/账务导出作为最终成本依据，关联 request/account/project、币种、税费、折扣与结算周期；账单缺少请求粒度时只在可证实的账号/周期层面对账，不伪造逐调用精确费用。账单尚未到达则标记 provisional。
- 实时预算账本与财务对账分开：实际 usage 或账单晚到以幂等调整分录修正，不覆写历史审计，不因暂时无法关联就把成本记为零；未匹配差异单独展示，人工核对需留痕。
- 财务金额使用 Decimal/整数最小货币单位并显式带币种；汇率、折扣与价格版本可追溯。不得通过浏览器计算权威金额。供应商更正账单作为新的调整来源保留版本。
- SDK 停机/失联不把最终账单采集责任下放给业务进程；控制平面不可用时仍受既定硬预算边界限制，不能以“以后对账”授权超额消费。

当前：已实现独立 SQLiteCostLedger、USD 账单导入、幂等去重、不可变调整、请求差异汇总及管理员页面与审计。权威值来源是管理员导入的供应商账单，文件真实性由部署方验证；自动采集、多币种、税务折扣和商业中央账务未实现。
